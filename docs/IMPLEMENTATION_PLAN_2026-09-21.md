# RoleScout 개선 및 기능 확장 실행 계획

작성: 2026-09-21. 기준: `README.md`, 실제 `src/`, `server/`, `db/`, 기존 테스트를 대조한 코드 감사. 이 문서는 구현 범위와 검증 조건의 기준이며, 배포 상태 또는 외부 서비스의 현재 동작을 보증하지 않는다.

## 목표와 완료 조건

사용자에게 보여 주는 공고가 현재 연결된 **공개 ATS 보드의 실제 결과**라는 출처를 유지하면서, 프로필 편집 직후 검색 결과, 언어 판정, 개인정보 삭제, 동의, 신규 공고 구분을 일관되게 만든다. 변경은 원본 이력서·기존 사용자 데이터·기존 git 작업을 보존하며 작성하고, 배포 전에 로컬 D1 마이그레이션, API 테스트, lint, 타입 검사와 빌드를 확인한다.

## 1차: 현재 구현의 결함 해결 — 이 작업에서 진행

| 우선도 | 작업                    | 구현 및 수락 조건                                                                                                                                                                                           |
| ------ | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0     | 로그인 신뢰 경계 확인   | Sites가 인증 헤더를 제거·재주입하는지 실제 배포 경로에서 확인. 로컬 개발 프록시에서 클라이언트 ID 위조 차단. 프로덕션 증거 없이 안전하다고 선언하거나 서비스를 중단시키는 임의 헤더 검사를 도입하지 않는다. |
| P1     | 개인정보·저장 정합성    | 계정 데이터 전체 삭제 시 사용자별 사용량 이력까지 삭제. 업로드와 DB 메타데이터 저장 중 실패 시 R2 객체 정리, 원본 보관은 명시적 선택. 다른 계정의 데이터는 영향받지 않음.                                   |
| P1     | API 입력 및 사용량 제한 | Content-Length가 없더라도 최대 본문 크기를 제한. 유효하지 않은 입력은 분석 사용량을 낭비하지 않게 처리. 경계값·실패 회귀 테스트.                                                                            |
| P1     | 검색 결과의 정확성      | 프로필의 점수/제외 조건/언어가 바뀌면 60초 재사용 결과 무효화. 한국어·Korean을 동일 언어로 취급하고 직무에 여러 언어가 요구될 때 잘못 통과시키지 않음. 점수순 기본 정렬과 UI 문구 일치.                     |
| P2     | 출처와 데이터 품질      | 북한 등 지명 오탐 방지, 식별자 쿼리를 포함한 URL 중복처리, 외부 URL 안전성, 일부 출처 실패 표기·기존 결과 보존 정책. 수집 날짜와 모집상태는 조회 당시 근거로만 표시.                                        |

## 2차: 외부 자격증명 없이 제공 가능한 신규 기능 — 이 작업에서 진행

| 기능                | 구현 및 수락 조건                                                                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LinkedIn URL 보관   | 사용자가 입력한 프로필 URL 형식 검증·계정별 저장·재접속 복원·계정 삭제 반영. URL 자동 방문/스크래핑은 하지 않음. 제공한 프로필 PDF/텍스트는 기존 문서 경로로 읽음.                          |
| 문서 처리 동의      | 분석할 텍스트·프로필 저장을 사용자에게 설명하고 확인받음. 이력서 원본 R2 보관은 별도로 선택하고 UI에 보관 상태·삭제 경로를 표시.                                                            |
| 신규 공고 표시      | *이전 성공 검색*과 새로 완료된 검색의 공고 ID 차이를 표시. 첫 검색, 캐시 재사용, 출처 부분 실패에는 신규라고 단정하지 않음. 사용자가 다시 검색해야 확인되는 인앱 비교이며 푸시 알림이 아님. |
| 공고 문구 주의 신호 | 선입금·금전 요구의 명시적 표현만 근거 문구와 함께 표시. 자동 사기 판정, 운영 주체 검증, 지급 보증으로 표현하지 않음. 부정문 및 정상적인 보수 공고 회귀 테스트.                              |
| 운영 테스트         | 사용자 격리, 삭제, 프로필 갱신, URL·언어·정렬·주의 문구 테스트를 추가하고 CI에서 자동 실행.                                                                                                 |

## 검증 및 출시 기준

1. `npm run db:local`, `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build` 통과. 기존 `dist/`가 필요하면 독립 임시 작업본으로 빌드 검증.
2. 실제 ChatGPT Sites 배포 경로에서 위조 ID 헤더가 계정 A/B의 데이터를 가져오지 못한다는 것을 확인. 로컬 모의 인증 통과만으로 운영 인증을 검증했다고 주장하지 않음.
3. 실제 ATS 3곳을 각각 호출하여 응답 구조/원문 링크를 확인하고, 표본 공고 20–50건의 언어·보수·한국 근무 여부·매치 점수 오분류를 사람이 검토. 자동 테스트 성공은 추천 정확성의 증거가 아님.
4. R2 원본 저장 동의, 원본 삭제, 전체 데이터 삭제, 반복 분석 및 검색의 실제 UI 절차를 확인하고 기존 데이터 백업·복구 절차를 수립한 뒤 배포.
