# 글로벌 맞춤 채용 공고 탐색 서비스 — PRD 초안

> 작성일: 2026-09-04  
> 상태: Discovery / MVP 범위 합의 전 초안

## 1. 제품 한 줄 정의

사용자가 이력서 또는 LinkedIn 기반 경력 정보를 제공하면, 그 정보를 구조화해 현재 열려 있는 글로벌 채용 공고를 찾아 **지원 적합도와 핵심 근무 조건을 비교 가능한 표로 제시**하는 서비스.

## 2. 확정된 요구사항

| 구분 | 내용 | 확신 |
|---|---|---|
| 대상 시장 | 글로벌 | 사용자 확정 |
| 입력 | 이력서 업로드와 LinkedIn 관련 입력을 모두 시험 | 사용자 확정 |
| 우선 작업 | 코드 구현 전에 제품·기술·데이터 전략을 정리 | 사용자 확정 |
| 결과 화면 | 직무명, 회사, 직무 내용, 보수, 근무형태, 근무시간 등을 한눈에 볼 수 있는 테이블 | 사용자 확정 |

## 3. 문제와 사용자 가치

구직자는 여러 국가·회사·채용 플랫폼에 흩어진 공고를 일일이 읽고, 자신의 경력과 조건에 맞는지를 판단해야 한다. 이 서비스는 다음을 한 화면에서 제공한다.

1. **프로필 정규화**: 이력서에 흩어진 경력, 기술, 학력, 언어, 희망 조건을 검색 가능한 프로필로 변환한다.
2. **공고 정규화**: 출처마다 다른 직무·근무지·보수 표기를 공통 스키마로 통일한다.
3. **설명 가능한 추천**: 점수뿐 아니라 “왜 맞는지”와 “부족하거나 불명확한 조건”을 보여준다.
4. **지원 판단 가속**: 보수, 원격 여부, 계약 형태, 시간대, 비자 조건 등을 비교·필터링한다.

### 3.1 초기 사용자군과 확장 원칙

| 구분 | 초기 범위 | 장기 확장 방식 |
|---|---|---|
| 핵심 사용자 | 한국에 거주하며 글로벌 원격근무 또는 한국 내 글로벌 기업의 직무를 찾는 사용자 | 국가·언어·근무 권한·현지 급여 체계가 다른 사용자까지 확장 |
| 우선 언어 | 한국어 UI + 영어 공고 이해/지원이 가능한 사용자 | 프로필·공고·추천 근거의 다국어 표시 |
| 우선 공고 | 글로벌 원격, 한국 소재 기업, 한국에서 채용하는 외국계 기업 | 국가별 로컬 공고와 현지 채용 파트너로 확대 |
| 제품 원칙 | 1인 사용자의 실제 구직 시간을 절약하는 정확한 추천 | 테넌트 분리·권한·동의·감사 로그를 갖춘 다중 사용자 서비스 |

**제품 결정**: 초기에는 개인 사용자의 프로필 하나를 깊이 있게 지원하되, 데이터 모델과 권한 구조는 처음부터 `User → CandidateProfile`의 1:N 관계를 유지한다. 이로써 한 사용자가 여러 버전의 프로필(예: 언어 데이터 직무용/기술직용)을 관리하거나, 이후 여러 사용자가 가입해도 데이터 구조를 다시 설계할 필요를 줄인다.

### 3.2 초기 직무 가설 — 이력서 확인 전

사용자가 언급한 `AI annotation`, `language transcription`을 출발점으로, 아래 직무군을 **초기 탐색 사전**에 포함한다. 이는 사용자의 실제 이력서를 아직 확인하지 못한 상태에서의 가설이며, 필수 기술·언어·경력 조건은 이력서 업로드 후 재설정한다.

| 직무군 | 탐색할 공고 제목·키워드 예시 | 분리해 봐야 할 조건 |
|---|---|---|
| AI 데이터 주석 | AI Data Annotator, Data Labeler, AI Trainer, RLHF Rater, Data Quality Specialist | 업무 언어, 계약직/프리랜서 여부, 평가 방식, 국가 제한 |
| 언어 데이터·전사 | Transcriptionist, Transcription QA, Speech Data Annotator, Linguistic Data Specialist | 한국어/영어 등 대상 언어, 화자 데이터 취급, 시간당/건당 보수 |
| AI 평가·품질 | AI Evaluator, LLM Evaluator, AI Response Rater, Trust & Safety Analyst | 전문성 요건, 콘텐츠 노출 위험, 보안·NDA, 교육 기간 |
| 로컬라이제이션·언어 품질 | Korean Language Specialist, Localization QA, Linguistic QA, Language Reviewer | 한국어 원어민 요건, CAT 도구, 검수 기준, 지역/시간대 |
| 데이터 운영 | Data Operations Associate, Content Operations, Dataset Curator | 운영/분석 비중, SQL·도구 요구, 고용형태 |

**주의**: 위 직무군에는 프로젝트·프리랜서·독립 계약자 형태가 많은 경우가 있으므로, 일반 정규직 공고와 섞어 추천하지 않는다. 계약 형태, 지급 기준(시급/프로젝트/연봉), 최소 보장 시간, 세금·근무 자격 정보를 별도 필터로 노출한다.

실제 이력서를 기준으로 만든 첫 검색 프로필과 키워드는 [INITIAL_SEARCH_PROFILE.md](INITIAL_SEARCH_PROFILE.md)에 기록한다. 이 문서는 개인화 검색 검증용이며, 이력서에 명시되지 않은 정보는 ‘미확인’으로 유지한다.

## 4. MVP 사용자 흐름

```text
가입/로그인
  → 이력서 업로드 및/또는 LinkedIn 정보 입력
  → AI가 구조화한 프로필 검토·수정
  → 희망 국가·직무·보수·근무방식 설정
  → 공고 수집·정규화·적합도 산정
  → 추천 테이블 탐색 / 필터 / 저장 / 원문 공고로 이동
```

### 4.1 입력 방식

| 방식 | MVP 포함 | 처리 방식 | 비고 |
|---|---:|---|---|
| PDF 이력서 | 예 | 텍스트 추출 → 구조화 | 필수 |
| DOCX 이력서 | 예 | 텍스트 추출 → 구조화 | 필수 |
| 이력서 텍스트 붙여넣기 | 예 | 바로 구조화 | 파일 파싱 실패 대비 |
| LinkedIn 공개 URL | 제한적 | URL 보관 및 사용자가 제공한 텍스트/파일과 연결 | URL 자체를 일반 크롤링하지 않음 |
| LinkedIn 프로필 PDF 또는 데이터 내보내기 | 예 | 업로드 → 구조화 | 권장 LinkedIn 경로 |

### 4.2 LinkedIn 처리 원칙

**확인된 사실**: LinkedIn은 사용자가 자신의 데이터를 다운로드할 수 있는 경로를 제공한다.  
**제품 결정**: MVP에서는 사용자의 LinkedIn URL을 자동 방문·스크래핑해 프로필을 추출하지 않는다. 대신 (a) URL 기록, (b) 프로필 PDF/내보낸 데이터 업로드, (c) 프로필 텍스트 붙여넣기를 제공한다.

이 결정은 로그인 상태, 접근 제한, 서비스 약관 변화에 좌우되는 URL 직접 분석을 핵심 기능으로 삼지 않기 위한 것이다. 향후 공식 권한형 연동이 가능하고 사업·법무 검토가 끝난 경우에만 OAuth 기반 연동을 별도 검토한다.

### 5.1 필수 필터

- 국가/지역, 시간대, 원격·하이브리드·오피스
- “한국에서 근무 가능”, “한국 법인”, “APAC 대상”, “글로벌 원격” 공고 범위
- 직무군/직급, 고용 형태, 언어
- 통화와 최소 보수(명시된 공고만)
- 게시·갱신일, 적합도, 저장 여부, 신뢰할 수 있는 출처 여부
- 비자 스폰서·근무 자격 조건(데이터가 제공되는 경우)

### 5.2 조건 입력과 테이블 표시의 원칙

사용자는 처음부터 희망 보수, 계약 형태, 주당 가능 시간, 계약 가능 국가 같은 선호 조건을 채울 필요가 없다. MVP는 **이력서에서 추출한 경력과 사용자가 제공한 공고 검색어**만으로도 결과를 보여 준다.

- 공고 원문에서 얻은 보수, 통화·지급 기준, 계약 형태, 근무 방식, 근무시간, 국가 제한, 비자·근무 권한 조건은 각각 독립된 테이블 열에 표시한다.
- `보수`는 `최소값`, `최대값`을 숫자로 저장·표시한다. `통화`와 `지급 기준`(시급/연봉/프로젝트)은 별도 열로 분리한다.
- 값이 비어 있으면 추정하지 않고 `미기재`로 표시한다.
- 사용자가 나중에 자신의 선호 조건을 입력하면, 그때부터는 추천 순서에 반영하거나 저장한 필터로 사용할 수 있다. 기존 공고를 숨기거나 자동 탈락시키지는 않는다.
- 계약 형태와 보수는 독립적으로 필터링한다. 보수 필터는 먼저 지급 기준(예: 시급)을 선택하고, 그 안에서 최소·최대 숫자 범위를 비교한다. 통화가 다른 값은 자동 환율 변환 없이 별도 확인한다.
- 모든 주요 조건 열은 정렬·필터 가능해야 한다. 예: `계약직만`, `시급 20 이상`, `보수 명시 공고만`, `한국 근무 가능 확인`, `주당 최소 시간 미기재 제외`.

## 7. 적합도 산정 원칙

초기 모델은 투명성을 우선한다. 아래 항목을 가중치로 합산하되, 사용자가 항목별 근거를 열람할 수 있어야 한다.

| 항목 | 초기 가중치 제안 | 판단 근거 |
|---|---:|---|
| 필수 기술·직무 경험 | 35% | 공고의 필수 자격과 검증된 경력 |
| 직무·직급·경력 연차 | 20% | 희망·현재 역할과 요구 수준 |
| 위치·원격·근무 권한 | 15% | 지원 가능성에 직접 영향 |
| 산업·도메인 경험 | 10% | 도메인 일치도 |
| 언어·학력·자격 | 10% | 공고상 요구 조건 |
| 사용자 선호 조건 | 10% | 보수·고용형태·시간대 등 |

점수는 추천 순서를 위한 보조 지표이며, “채용 가능성”이나 “합격 확률”로 표현하지 않는다. 필수 조건의 정보가 사용자 프로필에 없으면 불일치가 아니라 **확인 불가**로 표시한다.

## 8. 공고 데이터 전략

### 8.1 MVP 우선순위

1. **공개 ATS 채용 보드 API**: Greenhouse, Lever, Ashby처럼 회사가 공개한 자사 채용 보드 데이터를 우선 수집한다.
2. **회사 공식 채용 페이지**: 허용 범위와 기술적 안정성이 확인된 회사 단위 커넥터를 추가한다.
3. **상용/제휴 데이터 제공자**: 글로벌 범위와 커버리지가 필요한 단계에서 계약·라이선스 검토 후 도입한다.
4. **국가별 공개 고용 데이터**: 국가별 라이선스·재배포 조건을 검토해 선택적으로 추가한다.

공고 수집 작업은 우선 다음 세 개의 검색 버킷으로 공통 태그를 부여한다.

| 버킷 | 판정 기준 | 사용자 표시 예 |
|---|---|---|
| Global Remote | 원문이 원격 근무를 허용하며 국가 제한이 없거나 한국이 허용 대상 | 글로벌 원격 / 한국 가능 여부 확인 |
| Korea-based | 근무지가 대한민국이거나 한국 법인·오피스 기준 | 한국 근무 / 원격·하이브리드 여부 |
| Foreign company hiring in Korea | 외국계 기업의 한국 직무 또는 한국 대상 채용 | 외국계 한국 채용 |

공고 원문이 "remote"라고만 표기한 경우 한국에서의 실제 근무 가능 여부는 확정할 수 없다. 따라서 국가 제한·근무 권한 조건을 추출하지 못했으면 **“원격, 한국 가능 여부 미확인”**으로 표시한다.

### 8.2 확인된 외부 API 사실

| 공급자 | 확인된 기능 | MVP 활용 | 한계 |
|---|---|---|---|
| Greenhouse Job Board API | 회사의 공개 공고·부서·오피스 데이터를 JSON으로 제공, 공개 GET은 인증 불필요 | 회사별 공고 수집 | 전 세계 통합 검색 API는 아님; 각 회사의 board token 필요 |
| Lever Postings API | 사이트별 공개 채용 공고 목록 및 개별 공고 제공 | 회사별 공고 수집 | 전체 공고에 대한 full-text 검색은 제공하지 않음 |
| Ashby Job Postings API | 조직의 공개 공고 제공, 선택적으로 보수 정보 포함 가능 | 보수 데이터가 명시된 공고 확보 | 회사별 job board 식별자 필요; 누락 필드 가능 |

따라서 “글로벌 전체 공고”는 첫 출시에서 보장 가능한 사실이 아니다. MVP의 정확한 표현은 **“연결된 공개 채용 보드 및 제휴 데이터 소스 내 글로벌 공고 검색”**이어야 한다.

### 8.3 출처·플랫폼 신뢰도

공고 적합도와 별도로, 수집 경로·공식 원문 일치 여부·지급/분쟁 절차 공개 여부·명백한 사기 위험 신호를 보여 준다. 신뢰도는 사기 여부를 법적으로 판정하거나 개인별 지급을 보장하는 점수가 아니다. 상세 정책, 데이터 모델, 위험 신호와 단계별 범위는 [SOURCE_TRUST_AND_INGESTION.md](SOURCE_TRUST_AND_INGESTION.md)를 따른다.

## 9. 기술 아키텍처 제안

```text
Next.js 웹 앱
  ├─ 인증 / 프로필 편집 / 추천 테이블
  └─ API 계층
       ├─ 파일 업로드·문서 텍스트 추출
       ├─ 프로필 구조화 및 사용자 검토
       ├─ 공고 커넥터 (Greenhouse / Lever / Ashby ...)
       ├─ 정규화·중복 제거·갱신 작업
       └─ 매칭·설명 생성

PostgreSQL
  ├─ 사용자·프로필·권한
  ├─ 원문/정규화 공고
  ├─ 매칭 결과·저장 공고
  └─ 데이터 출처·수집 이력

Object Storage
  └─ 암호화된 원본 이력서 (텍스트·파생 데이터와 분리)
```

초기 구현 후보는 **Next.js + TypeScript + PostgreSQL + Prisma + S3 호환 파일 저장소**다. 공고 수집과 재매칭은 웹 요청과 분리된 작업 큐/스케줄러로 실행한다.

## 10. 개인정보·신뢰·컴플라이언스 요구사항

- 이력서 원본, 추출 텍스트, 구조화 프로필을 분리하고 사용자별 접근 통제를 적용한다.
- 사용자는 프로필 필드를 검토·수정하고, 원본 및 파생 데이터를 삭제할 수 있어야 한다.
- 파일 보관 기간과 AI 처리 목적을 업로드 전 명확히 고지하고 동의를 받는다.
- 공고마다 출처 URL, 마지막 수집 시각, 데이터 누락 여부를 표시한다.
- 연봉·근무시간·비자 조건은 원문에 없으면 추정값처럼 보이게 채우지 않는다.
- 출시 대상 국가별 개인정보 규정, 데이터 재배포 조건, ATS 및 구직 사이트 약관은 출시 전 법무 검토가 필요하다.

## 11. MVP 비범위

- 서비스 안에서의 원클릭 지원 및 이력서 자동 제출
- 합격률 예측·자동 탈락 판정
- LinkedIn 프로필의 무단 자동 스크래핑
- 모든 국가·모든 채용 사이트의 완전한 커버리지 보장
- 공고에 없는 보수·근무시간의 자동 추정 표시
- 플랫폼 또는 공고의 사기 여부·지급 보장에 대한 자동적·법적 단정

| 단계 | 목표 | 완료 기준 |

## 13. 다음 결정이 필요한 항목

아래는 아직 사용자 결정이나 검증이 필요한 가설이다.

1. **이력서 기반 키워드 확정**: 실제 이력서에서 직무 경험, 언어, 도구, 선호 고용형태를 추출해 3.2의 가설을 갱신해야 함.
2. **MVP 공고 범위**: AI 데이터·언어 데이터 직군으로 먼저 제한할지, 인접 직무까지 포함할지.
3. **국가 우선순위**: 우선 ‘한국 근무 가능’과 ‘글로벌 원격’을 모두 추적하되, 각 공고의 국가 제한을 어떤 정확도로 판정할지.
4. **수익 모델**: 개인 구독, 프리미엄 매칭, B2B 커리어 코칭/채용 파트너십 중 어떤 가설을 검증할지.
5. **AI 제공 범위**: 추천·설명까지만 할지, 이력서 개선·커버레터 초안까지 포함할지.
