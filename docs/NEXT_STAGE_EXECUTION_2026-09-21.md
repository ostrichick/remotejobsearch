# RoleScout 다음 단계 개발·검증 기록

기준일: 2026-09-21. [이전 개선 계획](IMPLEMENTATION_PLAN_2026-09-21.md)의 후속 단계이며, 이 파일은 실제 실행 및 수락 조건을 기록한다. 코드 구현과 운영 환경 검증, 외부 사이트 확인, 추천 품질 검수는 각각 별개의 상태다.

## 목표와 작업 순서

1. **운영 안정성(A)**: Sites 인증 헤더 신뢰 경계와 로컬 프록시를 감사하고, D1/R2 비파괴 백업·복구 절차 및 운영 배포 체크리스트를 제공한다. 배포는 인증 위조 테스트와 복원 리허설까지 통과하기 전 수행하지 않는다.
2. **추천 품질 검수(B)**: 저장된 본인 검색 결과에 대해 직무 적합성, 언어 판정, 한국 근무 여부, 보수 추출 결과를 사람이 평가하고 평가 시점의 공고 ID·점수·알고리즘 버전과 함께 보관한다. 평가 수정·삭제와 집계는 사용자별 격리를 지키고 결과의 분모와 미평가 수를 표시한다.
3. **ATS 확장 기반(C)**: 현재 확인된 Lever·Greenhouse·Ashby 기업 보드 세 개의 수집 계약·검증·오류 처리를 공통 구조로 분리한다. 실제 공식 식별자와 이용 조건을 확인하지 않은 회사를 채워 넣어 목표 출처 수를 맞추지 않는다.
4. **통합 검증(D)**: 새 DB 마이그레이션, 테스트, lint, 타입 검사, 클라이언트/서버 빌드를 별도 작업 복사본에서 통과시킨다. 기존 미커밋 소스와 원본 로컬 DB·R2를 보존한다. 단, 아래 기록대로 원본 `dist/`는 중간 빌드에서 재생성되었다.

## 각 산출물의 수락 기준

| 산출물      | 수락 조건                                                                                                                                                                        |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 로컬 인증   | 외부 요청이 임의로 넣은 인증 ID로 다른 계정의 API 데이터에 접근할 수 없고, 정상 개발 로그인도 유지됨. 운영 Sites 헤더 치환 검증은 별도 증거가 필요.                              |
| 백업·복구   | 명시적 대상만 복사하며 덮어쓰기 전 중지하는 안전한 명령과 테스트용 복원 절차를 제공. 실운영 DB/R2에 접근하지 않음.                                                               |
| 평가 UI/API | 본인 검색 공고만 평가 가능, 잘못된 입력/다른 사용자 접근 거부, 재평가와 삭제 가능, 버전·근거·분모 및 미검수 구분. 개인 이력서와 전체 공고 설명은 평가 기록에 중복 저장하지 않음. |
| ATS         | 기존 보드 세 곳과 기존 `Job` 계약 유지, URL 출처·캐시·부분 실패 회귀 테스트. 공개 URL의 실제 조회 결과는 조회 일시·HTTP 상태로 별도 보고.                                        |
| 품질 검증   | 실제 공고 20~50건에 대한 사람이 수행한 블라인드/수동 검수 후에만 정량적 정확도 주장. 소수 검수 자료로 성능을 일반화하지 않음.                                                    |

## 이번 단계 범위 밖의 의존성

- **실서비스 인증 검증**: 배포된 Sites 경로, 적법한 테스트 계정 두 개, 운영 접근 권한이 있어야 확인 가능. 로컬 헤더 검증 테스트만으로 대체하지 않는다.
- **운영 마이그레이션/실데이터 복원**: DB 바인딩 및 운영 백업 대상 확인과 안전한 복구 절차 수립 후 별도 승인된 배포 절차에서 진행한다.
- **신규 기업 수집**: 해당 기업의 현재 공식 ATS 보드, API 및 이용 조건 확인 후 별도 등록한다.
- **정기 발송·AI 유료 호출**: 발송 자격증명/수신 동의 또는 API 비용 설정과 사용자의 데이터 전송 선택이 필요하다. 이번 단계에서 임의 활성화하지 않는다.

## 검증 결과

### 구현 완료

- **A — 로컬 인증·복원**: `vite.config.ts`가 클라이언트 제공 인증 헤더를 제거한 다음 Sites 개발용 로그인 정보만 전달한다. 실제 Vite HTTP 기반 `tests/dev-auth.test.ts`에서 비로그인 신원 위조 401, 개발용 로그인 200, 로그인 상태의 다른 ID 위조 무효, 로그아웃을 확인했다. `scripts/backup-local.ps1`과 `scripts/restore-local.ps1`은 로컬 `.wrangler/state/v3`의 D1/R2를 명시된 새 위치에만 복사하고 SHA-256 manifest로 검증한다. 합성 D1/R2 상태의 백업·복원 해시 일치, 기존 대상 거부, 조작된 백업 거부를 확인했다. 실제 DB에 대한 백업/복원 또는 운영 Sites 인증은 검증하지 않았다. 구체적 절차는 [운영 점검표](OPERATIONS_RUNBOOK.md).
- **B — 사용자별 수동 품질 평가**: D1 `job_evaluations` 테이블과 마이그레이션 `0002_boring_ben_grimm.sql`, 본인 검색 결과에 한정한 평가 CRUD, 관련성·한국 근무·언어·보수 평가 UI, 평가 시점 점수/버전 스냅샷, 분모가 표시된 집계 및 CSV/JSON 내보내기를 구현했다. 메모는 내보내기에서 기본 제외되며 계정 전체 삭제 시 평가도 삭제된다. 실제 20~50건을 사람이 평가한 것은 아니다. 검수 기준은 [수동 검수 프로토콜](RELEVANCE_REVIEW_PROTOCOL.md).
- **C — 수집 구조**: 기존 Welo Lever·Coupang Greenhouse·Mercor Ashby 세 곳만 `server/ats/index.ts` 공통 설정·공급자별 응답 파서로 분리했다. malformed 응답과 외부 지원 링크 출처 상태에 회귀 검사를 추가했다. 2026-09-21 04:59~05:04 UTC에 개인정보 없이 공식 공개 API 세 곳 모두 HTTP 200, JSON과 공급자별 응답 envelope를 확인했다. 첫 실제 Welo 전체 응답을 새 엄격 파서에 통과시켰을 때 숫자형 `createdAt` 때문에 전부 거부되는 회귀가 발견되어 숫자 타임스탬프 처리 및 테스트를 수정했다. **수정 후 전체 Welo 실시간 공고 수집 건수는 재검증하지 못했으므로 실서비스 정상 동작을 확정하지 않는다.** Coupang 응답 705개 중 구조 검증 705개, 지역 기준 374개이며 링크는 외부 도메인임을 표시한다. Mercor는 109개 중 구조 검증 108개, 지역 기준 1개였다. 이 수치는 해당 시간의 원본 응답 구조/필터 확인 결과로, 맞춤 추천 건수나 실제 모집 확약이 아니다.

### 독립 통합 검증

프로젝트 내부 `tmp/verify-*`의 격리 복사본에 추적 파일과 공개·신규 소스 73개를 복사해 검증했다. 로컬 개인 검수 자료 `docs/INITIAL_SEARCH_PROFILE.md`는 복사하지 않았다. 아래 명령은 같은 격리 복사본에서 순차 실행했고 **전체 종료 코드 0**이었다.

| `npm test`         | 57개 통과 / 실패 0개 (실제 로컬 Vite 인증·D1/R2 통합 테스트와 메모리 SQLite 평가 테스트 포함)         |

### 미검증 게이트와 변경 중 발생한 사항

- **실제 배포 전 필수**: 운영 Sites가 인증 ID 헤더를 제거·재주입하는지 실제 두 계정으로 검증해야 한다. 실제 D1/R2 바인딩·스냅샷·운영 마이그레이션, 모바일/데스크톱 UI 흐름, 사람의 실제 공고 20~50건 품질 검수도 완료되지 않았다. 작업 중 배포·원격 마이그레이션·API 비용 발생 작업을 수행하지 않았다.
- **기존 `dist/` 재생성 고지**: 작업자 중 한 명이 격리 빌드 안내를 수신하기 전에 원본 프로젝트에서 `npm run build`를 실행했다. 이 명령은 `scripts/clean-build.mjs`를 실행하므로 기존 Git 무시 대상인 `dist/` 산출물이 새 빌드로 교체되었을 수 있으며 기존 버전의 사본은 확보하지 못했다. 소스·사용자 DB·R2 자료를 삭제하거나 운영 배포한 것은 아니지만 `dist/` 보존을 달성했다고 주장하지 않는다.
