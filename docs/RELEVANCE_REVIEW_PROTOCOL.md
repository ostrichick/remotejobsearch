# RoleScout 공고 검색 수동 검수 프로토콜

2026-09-21 기준. [다음 단계 실행 기록](NEXT_STAGE_EXECUTION_2026-09-21.md)과 함께 사용한다. 이 문서는 검수 **방법**이며 20~50건의 실제 검수가 완료되었다는 뜻이 아니다.

## 검수 표본 확보

1. 본인 계정의 검색 프로필을 저장하고 채용 출처 세 곳에 대해 성공한 검색 결과와 각 출처의 조회 시간을 기록한다. 일부 출처가 실패했거나 캐시가 오래되었다면 별도 상태로 표시하고 전체 검색 성공 표본에 섞지 않는다.
2. 가능하면 목표 직무군(한국어 AI 평가, 데이터 어노테이션, 언어 검수, 교육 등)을 다양하게 포함하고, 높은·중간·낮은 점수에서 고르게 20~50건을 추출한다. 화면에 없는 저점수 공고는 별도 출처 샘플로 검토해야 검색의 *누락률*을 평가할 수 있다.
3. 각 공고의 공식 ATS 제공 링크를 직접 열어 게시 시점, 한국 거주 지원 자격, 복수 요구 언어, 보수의 통화·지급 단위·하한 여부를 확인한다. 명시되지 않은 항목은 긍정/부정으로 추정하지 않고 미확인으로 기록한다.
4. 가능한 경우 규칙 기반 점수를 가리고 먼저 사람의 관련성 판정을 기록한다. 날짜·출처·검색 프로필의 변경 여부·점수 버전을 함께 기록하고, 공고에 개인정보가 있다면 복사·공유하지 않는다.

## 판정 기준

| 항목      | 판정                           | 근거 예시                                                     |
| --------- | ------------------------------ | ------------------------------------------------------------- |
| 관련성    | 적합 / 부적합 / 불확실         | 공고 주요 업무와 프로필의 명시된 직무·역량이 직접 일치하는가? |
| 한국 근무 | 가능 명시 / 불가 명시 / 미확인 | 명시적 지역·거주 조건. 원격 근무만 적혀 있으면 미확인.        |
| 언어      | 정확 / 부정확 / 미확인         | 필수 언어와 사용자 보유 언어가 모두 맞는지 확인.              |
| 보수 추출 | 정확 / 부정확 / 미확인         | 최저·최고 금액, 통화, 시급·프로젝트당 등 단위가 일치하는가?   |

사람의 검수값은 평가자의 판정이지 외부 기업의 지원 승인, 법적 취업자격 확인 또는 사기 여부 확정이 아니다. 메모는 판정에 필요한 짧은 이유만 입력하고 개인 연락처·이력서 원문을 붙여 넣지 않는다.

## 최소 지표와 분모

- **평가 완료율** = 평가된 공고 수 / 검수 대상 공고 수. 대상의 범위를 명시한다.
- **관련성 판정 가능 수** = 적합 + 부적합. 불확실과 미평가는 분모에서 제외하되 건수를 별도로 표시한다.
- **앱의 관련 공고 표시와의 불일치 비율** = 점수 45점 이상 중 사람이 부적합이라 판정한 건수 / 점수 45점 이상이며 적합 또는 부적합으로 판정된 건수. 현행 앱의 `medium` 이상 경계값과 동일하다. 점수 70점 이상인 `high` 공고만 별도 분석할 때에는 그 범위와 분모를 구분해 표시한다.
- **지역/언어/보수 추출 일치율** = 해당 항목을 사람이 검증한 공고 가운데 자동 판정과 일치하는 수 / 해당 항목 검증 가능 건수. 모호한 '미확인'을 임의로 맞음으로 간주하지 않는다.
- **검색 누락 평가**는 검색 결과만 검수해서는 산출할 수 없다. ATS 원본 전체 또는 별도의 독립적 관련 공고 목록에 대한 검수가 추가로 필요하다.

검수 수 20~50개는 탐색적 회귀 검증이며 서비스 전체 정밀도·재현율의 통계적 보증은 아니다. 평가자가 한 명이면 평가자 간 일치도 또한 측정할 수 없다.

## 규칙 변경 후 재검증

같은 출처 스냅샷·프로필·표본에서 구 버전과 신 버전 점수를 비교하고, 개선/퇴보 사례를 테스트 픽스처로 등록한다. 공고 원문이나 직무 요구가 바뀐 경우는 이전 버전과 직접 동일 조건 비교하지 않는다. 점수 기준 또는 검색 필터를 수정하면 `scoreVersion`을 업데이트하고 과거 평가를 새 알고리즘의 정확도 측정에 무비판적으로 합산하지 않는다.
